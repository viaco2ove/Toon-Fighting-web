# 取代关键帧
取代关键帧的意思是只把某几个帧取代，而不是全取代。
要不两种模式都展示看看效果差异。http://localhost:8100/ff-studio/src/viewer.html  增加 关键帧模式：全/抽
全就是你现在做的效果：只留下关键帧。
抽就是本来的动作 只改关键的那一帧。
「抽」模式的关键是：只有代表帧用 AI 图，其余帧保持原精灵
「融」模式的关键是：
角色资产标记：标记 为抽关键帧/全替关键帧/融合关键帧/不使用关键帧，并记录职业等信息。要影响到游戏运行时资产的信息。

## 资产标记的落地（2026-11-25）

标记写在**角色包目录的 `char.json`**：

```json
{
  "charId": "LinYu",
  "displayName": "林羽",
  "roleType": "player",
  "profession": "武道家",
  "keyframeMode": "some",
  "keyframeLabel": "抽关键帧",
  "keyframeCount": 10
}
```

`keyframeMode`：`some` = 抽关键帧（只换各动作的代表帧）/ `all` = 全替关键帧 / `none` = 不使用关键帧。

### 写入

- 查看器顶栏「资产标记」区：选关键帧模式 + 填职业 → 点【写入 char.json】→ `POST /api/charmeta`
- 服务端 `server/lib/packs.cjs` 的 `writeCharMeta()`：写到**引擎目录**优先
  （`ikemen-fs/file/chars/<id>/char.json`，实际跑起来的角色），
  没有才写资产集目录（`map_design/<dir>/chars/<id>/char.json`）。
  同一角色只写一处，避免出现两份不一致的标记。

### 运行时怎么用（要影响游戏运行）

1. `GET /api/assetpacks` 顺带下发 `charMeta`（`{ charId: meta }` 汇总）。
2. 前端 `PACKS.charMeta` + `charMeta(id)` / `keyframeModeOf(id)`：
   - **角色实体绑定**（故事会话 → 角色列表）：主角（`roleType: player`）排最前、
     带「主角」角标 + 「抽关键帧」标记，下拉框里的职业名取 `char.json` 的 `profession`。
   - **选人屏**：故事角色池里主角排第一，实体下拉同样显示职业。
   - **战斗头像条**：显示职业（`profession` 优先于内置 MUGEN 表的 `tag`）。
3. `roster.json` 的 `defCharacterAssets`：**默认绑定**到指定的引擎角色
   （`composeRoster` 里优先于随机分配）。角色池来自 `mapping.json` 的 `charPool`。

### 两个踩过的坑

1. **`packMeta` 的读取顺序**：原来是「登记目录优先、map_design 回落」。
   登记目录是登记时的快照，用户之后直接改 `map_design` 里的 `roster.json`
   （比如加 `defCharacterAssets`）就永远不生效。已改成 **map_design 优先**。
2. **角色池要同步**：`defCharacterAssets` 指向的角色必须在 `mapping.json` 的
   `charPool` 里，否则 `packCharPool().includes()` 为假 → 退回随机分配。
