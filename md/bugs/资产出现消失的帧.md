## 结论

**不是色块去除，也不是游戏显示问题，也不是 merge 技能的问题。是 SFF 写出器的 bug。**

### 根因

引擎 `Toon-WebMUGEN-2.0/ikemen-go-web/src/image.go`：

```go
// readPcxHeader：只有 encoding==1（RLE）才把 bpl 存进 s.rle；raw(encoding=0) 时 s.rle = 0
if encoding == 1 { s.rle = int(bpl) } else { s.rle = 0 }
// RlePcxDecode：s.rle<=0 时原样返回字节流 → px 长度 = bpl*h
// SetPxl (934): if len(px) != Size[0]*Size[1] { return }  ← 纹理不生成 → 精灵隐形
```

`Size = w*h`，raw 模式下 `px` 长度 = `bpl*h`。**`bpl ≠ w` → 整张精灵被引擎静默丢弃，不打任何日志。**

我们的写出器按 PCX 惯例把 `bpl` 补成偶数（`w + (w & 1)`）→ **所有奇数宽的合成精灵隐形**。苏晚晴站立 action 0 的 8 张合成精灵宽全是奇数（71/69/71…）→ 开局进站立循环人就消失。

**ff-studio 查看器为什么看不出来**：它按 `bpl` 跨距读行（`px[y*bpl+x]`），补齐字节被忽略 → 画面正常。查看器正常 ≠ 引擎正常。

### 反例已排除
原始包 `_原始包/LinYu/Lin.sff` 也是 `bpl=w+1`，但引擎实际读的是 `ikemen-fs/file/chars/Lin/Lin.sff`（丢弃 0）；且所有正常工作的原始包 raw 精灵都是 `bpl == w`。
