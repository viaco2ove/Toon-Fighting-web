# 角色包制作流程（用什么工具做、怎么改、发到哪、AI 能不能生成）

> 上游：[角色职业.md](../角色职业.md)（要哪些角色）、[下载源.md](./下载源.md)（去哪下别人的）、[资产制作.md](./资产制作.md)（下载回来后怎么入库）
> 本文回答：**角色包本体是怎么被做出来的**——工具链、从零制作、改造别人的包、发布上传渠道、以及 AI 生成可行性（2026-11 现状评估）。
核心内容：
- **工具链**：主力 IDE 是 **Fighter Factory Studio 3.7**（免费 LGPL，sff/snd/air/def 全格式可视化编辑）；cns/st/air/def 是纯文本所以直接用 VS Code 写；IKEMEN GO 专属的 **ZSS 格式**支持变量 / 函数 /if，对程序员更友好fighterfactory.virtualltek.com
- **从零制作流程**：KFM 模板起步 → 扒帧 / 自绘 / 拼装精灵帧（轴点对齐是关键）→ AIR 动画 + 碰撞盒 → CNS 状态机 → wav 音效，附工作量参考（编辑版 1-3 天 vs 全原创 2-8 周）
- **改别人的包**：按改动量列表 ——AI 闸、伤害数值、换色、加招式、换头像各自改哪
- **发布渠道**：MUGEN ARCHIVE / MFFA / DJB（同生态整包口径）/ 千寻 / 贴吧 B 站 / 自建 Drive + 目录页模式
- **AI 生成可行性（分层评估）**：CNS 逻辑代码 ✅ AI 主导（本项目 AI 闸补丁就是实例）、精灵帧 ⚠️ 半自动（帧间一致性是硬瓶颈）、头像 ✅ 已在 M5 规划走 agentRun 生图、整包端到端 ❌ 目前不成立 ——**现实路径是「下载现成包 + AI 改造」**

## 1. 工具链

角色包 = 5 类文件（def 入口 / sff 贴图 / cns+st 逻辑 / air 动画 / snd 音效），其中 **def/cns/st/air/cmd 全是纯文本**，只有 sff/snd 是二进制。所以工具链天然分两层：

### 1.1 二进制层（贴图/音效）

| 工具 | 用途 | 说明 |
|------|------|------|
| **Fighter Factory Studio 3.7**（VirtuallTek） | 主力 IDE：sff/snd/air/def 全格式可视化编辑，内置图像编辑器、动画预览、代码高亮 | 免费（LGPL），Win/Linux/macOS；官网 http://fighterfactory.virtualltek.com/ 。本项目首选 |
| **Audacity** | 音效剪辑 → 导出 wav 进 snd | MUGEN 音效只吃 wav |
| **Aseprite / Photoshop / GIMP** | 精灵帧绘制、改色、缩放 | 导出 PNG 后由 FF Studio 导入 sff |
| Sprite 分解/打包（FF Studio 自带导入导出） | sff ↔ PNG 批量互转 | 改贴图时先把 sff 拆成 PNG 目录，改完再打包回去 |

SFF 格式两代：v1（WinMUGEN 时代，调色板外挂 .act）与 v2（MUGEN 1.0+，调色板内嵌、支持 32 位 RGBA/PNG 压缩）。**IKEMEN GO 两代都支持**，所以新旧角色包都能收；新做包直接用 SFF v2，省掉调色板地狱。

### 1.2 文本层（逻辑/动画/定义）

- **任何代码编辑器**（VS Code）即可写 cns/st/air/def——这是社区二十年积累的核心资产：全部文本。
- **IKEMEN GO 专属：ZSS 格式**（Zantei State Script），可替代 CNS 写法，支持局部变量/函数/if 语句，对程序员友好；可与 CNS 混用（分文件）。参考引擎自带 `data/kfm_zss` 与 wiki（https://github.com/ikemen-engine/Ikemen-GO/wiki/ZSS）。
- 起步模板：引擎自带 **KFM**（`data/kfm.def` 全套），官方路径就是「照着 KFM 抄」——复制 KFM 的 air/cns 改名改帧是最短起步路径。

## 2. 从零制作一个角色（标准流程）

1. **立项**：FF Studio 新建 MUGEN 项目 → 以 KFM 为模板复制一套 def/air/cns。
2. **贴图**：精灵帧来源三选一——
   - 游戏素材站扒帧（The Spriters Resource 等，注意版权，见 §6）；
   - 自绘（Aseprite 逐帧画，640×480 坐标系下全身动画通常 100–500 帧）；
   - 用现有包的帧拼装（社区「编辑版」角色的普遍做法）。
   每帧在 FF Studio 里设 **axis（轴点）**，轴不一致动作就会抖。
3. **动画**：AIR 里把帧编号串成 action（如 40=起跳、200=轻拳），写循环/帧时长/碰撞盒（CLSN1 攻击判定、CLSN2 受击判定）。碰撞盒是手感的关键。
4. **逻辑**：CNS 写状态机——stand/turn/walk/jump 是引擎约定的公共/负状态；招式 = cmd 里定义指令 → cns 里 Statedef + ChangeState。防御/AI/受击全是状态控制器。
5. **音效**：Audacity 剪 wav → FF Studio 写入 snd → def `[Files]` 登记。
6. **调平衡**：damage、lifebar 数值、hitdef 参数集中在 cns 常量区。
7. **测试**：本地 MUGEN/IKEMEN GO 人机对战 + 训练模式看帧数据；本项目环境直接走 [资产制作.md](./资产制作.md) 入库流程 + verify 双阶段。

工作量参考：借 KFM 模板 + 现成帧拼装约 1–3 天/人；全新精灵从零画约 2–8 周/人。**社区 90% 的包是「编辑版」（拼装+改逻辑），从零画原创精灵的是少数**——这直接影响 §5 的 AI 评估。

## 3. 改别人的角色（本项目最高频操作）

按改动量从小到大：

| 需求 | 改哪 | 工具 |
|------|------|------|
| 关/开野 AI、调 AI 强度 | cns/st 里 `var(59)` 置 1 的 AI Start 块（本项目统一加 `TriggerAll = Ailevel > 0` 闸） | 文本编辑器 / `patch-char-ai.mjs` |
| 改招式伤害/出招帧 | cns 顶部常量 + 对应 Statedef 的 HitDef | 文本编辑器 |
| 换配色（P2/P3/P4 备选色） | sff 内嵌 palette（v2）或外挂 .act（v1） | FF Studio |
| 加招式 | cmd 加指令 + air 加 action + cns 加 Statedef | FF Studio + 文本 |
| 换立绘/头像 | sff 里 group 9000 系（portrait） | FF Studio |
| 修兼容 bug（1.0-only 语法、localcoords） | def `[Info]` 版本参数、cns | 文本编辑器 |

红线：改完别人的包**仅限自用/私有侧载**，二次分发要遵守原作者授权（多数包 README 写明禁止转传或要求署名）。

## 5. AI 能不能生成角色包？——分层的诚实答案

**结论：代码层 AI 已经能用甚至主导，贴图层只能半自动，整套全自动生成目前不成立。**

| 层 | 可行性 | 2026-11 现状 |
|----|--------|-------------|
| CNS/ZSS 招式逻辑、AI 代码、数值 | **✅ 高度可行，AI 主导** | 纯文本状态机是 LLM 强项；本项目 AI 闸补丁（4 个角色批量加 `Ailevel>0`）就是 AI 批量改的实例。给 AI 喂 KFM 模板 + 招式描述 → 产出可跑 cns 是现实工作流 |
| AIR 动画定义、def、cmd | **✅ 可行** | 同上，文本格式，规则清晰可校验 |
| 精灵帧（sff） | **⚠️ 半自动** | 瓶颈是**帧间一致性**：上百帧、逐帧轴点对齐、8-bit 索引色。AI 生图单帧质量可以，整动作序列抖动/跳帧严重，逐帧修轴的人工成本高于直接扒现成帧。现实路径：AI 出关键帧 → Aseprite 修帧补帧 → FF Studio 打包 |
| 音效（snd） | **✅ 可行** | TTS/SFX 模型生成喊招语音、打击音效，剪 wav 即可 |
| 头像/立绘（facebar avatarRef） | **✅ 已规划** | 本项目 M5 里程碑就是 AI 头像：走后端 `/plugin/agentRun`（field-survival-sprite-gener）按角色生成 avatarRef，前端双头像条已留好接入口 |
| 整包端到端生成 | **❌ 不成立** | 「一句话生成一个能打的 KOF 角色」需要帧级动画一致性，当前模型做不到；但「**AI 改造现有包**」（换皮、改招式、写 AI、生成头像+音效，帧复用原包）是当下就能跑通的工程路径 |

对本项目的落地建议：新角色优先走「下载现成包 + AI 改造」——AI 负责职业化数值、招式调整、野 AI 处理、头像生成与音效；精灵与骨架用原包资产。完全原创角色等 M5 之后按需立项。

## 5.2 轻量化角色资产
使用角色的头像文件png 或者webp 转png 对一个现有角色进行改造，让它看的像这个角色
甚至专门做个白模人物来实现，只在头上显示一些角色的头像（png or webp）。
## 5.2.1 白模 + 头像贴头：一套骨架量产故事 NPC

> 思路：用头像文件（png / webp→png）改造一个现有「白模」角色，让对局内的身体看起来是故事角色；本质是「一套骨架 × N 张头像」的工业化量产路线，与 M5 的 facebar avatarRef（UI 层头像）形成两层同源。

### 可行性判断

MUGEN 每帧贴图是「头+身体烤死在一张图里」，**没有骨骼分层，引擎运行时不能往角色头上叠图**。所以只有离线改图一条正路：

| 路径 | 做法 | 结论 |
|------|------|------|
| **A. 白模包逐帧贴头（推荐）** | 预处理头像 → FF Studio 导出 PNG 帧 → 脚本批量抹原头/贴新头 → 打包回 sff | ✅ 正路，脚本化后分钟级/角色 |
| B. Explod/Helper 运行时贴头 | helper 挂 explod 渲染头像跟随 p1 | ❌ 偏移表照样要标，转向镜像、不参与受击缩放，hack 味重；仅「对局中热换头像」玩法才考虑 |
| C. 只换 UI 层 | facebar avatarRef（已实现）+ sff 9000 系 portrait 换图 | ✅ 成本最低，选人/结算层「像」，对局层不像；与 A 组合使用 |

### 路径 A 实施步骤

1. **选白模基础包**：动作朴素、头型居中、幅度小的骨架（KFM 改灰白配色最稳），用调色板/重上色做成灰白素体。
2. **头像预处理**：webp → png（`ffmpeg`/PIL 一行）；头像要抠成**带透明底的头部图**（AI 抠图/生图正好干这个），导出 32-bit RGBA——IKEMEN GO 完整支持 SFF v2 混色深（8-bit 身体 + 32-bit 头像特效），免调色板对齐。
3. **导出帧**：FF Studio 把白模 sff 导出成 PNG 帧目录（按 group/action 分文件）。
4. **批量贴头脚本**（Node sharp / Python PIL，写一次半天~1 天）：
   - 每帧：定位颈部锚点 → 抹掉原头部区域 → 按 32-bit RGBA 贴头像 → 写回。
   - **锚点表是唯一的手工量**：头部位置随动作变（出拳低头、跳跃侧转），按 action 分组只标代表帧偏移（几十个 action 一次标完，组内插值）；进阶版用每帧人脸/头型检测自动对齐，正好是 AI 半自动的活。
5. **打包回 sff**（FF Studio 导入 PNG 目录）→ def 选默认 palette → 按 [资产制作.md](./资产制作.md) 入库四步 + verify 双阶段。

### 量产模型

- 脚本与锚点表沉淀一次；之后 **每个新故事 NPC = 一张透明底头像 png + 跑脚本 = 分钟级出新角色包**。
- 身体动作全同（一套白模）→ 所有白模 NPC 共享一个骨架的 air/cns，只换头；职业差异（数值/AI）由 AI 改 cns 批量生成，与 §5 结论闭环。
- 分工建议：AI 出头像图 + 批量脚本跑贴图 + AI 改数值；人工只做一次锚点表标定与抽查。

### 已知限制（提前说清）

- 所有白模 NPC 动作完全一样，玩多了能认出「都是一个模子」——故事 NPC 场景够用，主角/ Boss 级角色仍走下载现成包 + AI 改造（§5）。
- 大幅度转头动作（翻滚、倒地）贴头像会穿帮，锚点表里可对这些 action 直接保留白模头或用背影帧。
- 白模基础包记得核对授权（§6）。

## 6. 版权红线（制作侧）

- 扒帧/改造别人作品的包：自用与私有侧载可，**对外分发前必须核对原作者授权**。
- AI 生成部分：AI 产物（头像/音效/代码）版权归生成者与工具条款共同约束，混合包发布时分层声明。
- 本项目仓库/资产集依旧只存引用与元数据，资产本体不分发（对齐 NOTICE.md §5）。
