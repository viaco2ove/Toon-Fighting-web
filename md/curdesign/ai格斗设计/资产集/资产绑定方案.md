## 0. 一句话结论

**这是我们的设计问题，不是框架问题。**

引擎（Ikemen GO）本身完全支持「角色不从 `chars/` 目录来」——它支持 ZIP 角色包、支持按 def 所在目录相对解析附属资产、支持任意 VFS 路径；是我们自己的 BFF 与前端把「资产集里的角色」硬塞进了引擎的**默认资源目录** `ikemen-fs/file/chars/`，于是：

- 引擎目录被当成「资产集仓库」→ 一万个资产集就要往里塞一万份角色；
- 「本地缺少 N 个角色」告警变成一句自相矛盾的话（资产集的角色就在资产集目录里，却说它「本地缺少」）；
- 版权与分发边界糊了：引擎目录本该只放**兜底/默认**资产（可随站点分发的通用角色），现在却成了「用户资产的暂存地」。

正确做法：**引擎目录只放兜底资产，永远只读；资产集自带自己的资产，以「覆盖层」的方式在运行时挂进 VFS。** 绑定资产集 = 挂一个覆盖层 + 生成该资产集的角色名单，**零拷贝**。

## 1. 现状诊断（含证据）

### 1.1 症状

绑定 `moshi-v1`（末世选择资产集）后主界面出现：

```
⚠ 本地缺少 14 个角色：LinYu、LinYuKF、LinYuKFA、LinYuKFM、SuWanqingKFM、LinYueKFM、
   LaoLeiKFM、ChenAyiKFM、ZhaoDachuanKFM …
```

### 1.2 根因链

| 环节 | 位置 | 事实 |
|---|---|---|
| 告警来源 | `index.html:1426-1431` `missingPackChars()` | 用 `mapping.charPool` 减去 `PACKS.localChars` 求差 |
| 「本地角色」的来源 | `server/lib/packs.cjs:183-200` `LOCAL_CHARS_DIR = ikemen-fs/file/chars` | `localCharIds()` = **引擎目录下的子目录名** |
| 兜底名单 | `index.html:1236` `LOCAL_OK = ["LinYu","Lin","Hinako","K'","Rugal2nd","Leona"]` | 硬编码，且随后被 `localChars` 合并覆盖（`index.html:1343`） |
| 资产集自己的资产 | `workshops/toon-fighting-web/map_design/末世选择…/chars/` | 资产集目录里本来就有全部角色包（`.def/.sff/.cns/.air/.cmd/.act`） |

即：**判定「有没有这个角色」看的是引擎目录，而不是资产集目录。** 删掉引擎目录里那些拷贝（用户已经删了 `LinYu*` 一族），告警立刻从「齐了」变成「缺 14 个」——告警描述的是一个我们自己制造出来的假象。

### 1.3 设计层面的三个硬伤

1. **双向污染**：资产集 → 引擎目录（拷进去）→ 引擎目录 → 「本地有哪些角色」（读出来）→ 再去和资产集比对。同一个概念有两份真源。
2. **不可扩展**：资产集数量 × 角色数 = 引擎目录体积。`manifest.json` 按文件大小登记（AGENTS.md 机制 1），每加一个资产集都要重建清单；APK 还要全量打包（`android_h5/sync.mjs`），体积无上限增长。
3. **分发红线**：引擎目录里的东西会随站点 / APK 分发。第三方角色包一旦拷进去，就等于被我们二次分发了——这正是 AGENTS.md 里「引擎资产不入库」的初衷，只是执行时被绕过去了。

### 1.4 引擎侧事实（已核对源码，不靠猜）

| 事实 | 出处 | 含义 |
|---|---|---|
| 角色 def 查找根 = `""` 与 `"data/"`，默认子目录 `"chars/"` | `ikemen-go-web/src/system.go:5531` `SearchFile(charDefPathGuess, []string{"", "data/"}, "chars/")` | 角色 def 只要在 **`chars/` 下**就能被找到，与「谁拷进去的」无关 |
| def 的附属资产按 **def 所在目录**相对解析 | `system.go:5653` `LoadFile(&cns_orig, []string{sc.def, "", "data/"}, "")`；`compiler.go:8362` `stateCompile(..., []string{def, "", motif.Def, "data/"}, ...)` | `.def` 旁边放 `.sff/.cns/.air/.cmd/.act` 即可自洽，无需外部约定 |
| 支持 ZIP 角色包 | `system.go:5482-5519` `isZipChar` / `getDefaultDefPathInZip` | 资产集可用 zip 单文件封装角色（后续可选封装格式） |
| 角色 def 可带路径 | `script.go:3419` `addChar`；`system.go:5519`（含 `/` 则直接补 `.def`） | 可以传 `chars/LinYu/LinYu.def` 这种带目录的显式路径 |
| Lua 侧按字符串查表 | `external/script/main.lua:1526` `main.f_addChar`、`start.lua:1334` `start.f_getCharRef` | 只要引擎能解析出 def，角色名怎么写都行 → 前端可传完整相对路径 |
| `select.def` 来自 `data/select.def` | `ikemen-go-web/src/motif.go:81` `FilesProperties.Select` 默认 `select.def`，lookup `def,,data/` | 名单文件在 VFS 里 → 可被覆盖层替换 |

结论：**引擎侧不需要改一行 Go 代码**，只要「资产集的文件在 VFS 里以 `chars/<id>/<id>.def` 的形状出现」，一切照旧。

### 1.5 VFS 侧事实

| 事实 | 出处 | 含义 |
|---|---|---|
| 清单驱动懒加载 | `vfs.js:318-333` `fetchFile()` → `./ikemen-fs/file/<vpath>?v=<stamp>` | 资源按 `vpath` 单文件拉取，天然支持「按需只拉用到的角色」 |
| 清单只登记 `file/` 下的文件 | `.cache/scripts/rebuild-manifest.mjs` | 覆盖层里的文件**不进清单**，只能靠运行时注册 |

## 2. 目标架构

### 2.1 三层文件视图

```
┌─────────────────────────────────────────────────────────┐
│  L0  引擎兜底层（只读、可分发）                            │
│      ikemen-fs/file/  —— 通用角色 + stages/data/font       │
│      永不写入、永不因资产集而增长                          │
├─────────────────────────────────────────────────────────┤
│  L1  资产集覆盖层（每个资产集一份，按需挂载）               │
│      资产集自己的目录树，原样挂到 VFS 根：                │
│      chars/<id>/…  data/…  external/…  stages/…          │
│      优先级：同 vpath 时覆盖层 > 兜底层                     │
├─────────────────────────────────────────────────────────┤
│  L2  浏览器覆盖层（可选，用户自选文件夹 / Mod Studio）      │
│      IndexedDB `ikemen-mods`，复用 ikemenMods API          │
│      优先级：L2 > L1 > L0                                 │
└─────────────────────────────────────────────────────────┘
```

**绑定资产集 = 在 L1 挂一个覆盖层 + 换一份角色名单 + 换一份 `select.def`。不产生任何文件拷贝。**

### 2.2 路径命名约定

- 资产集目录里的一切**保持原样**（`chars/`、`data/`、`stages/`、`external/`…），不做前缀改造 → 资产集可以原封不动地打包分发。
- 挂载后它在 VFS 里的 vpath **就是它自己的相对路径**（`chars/LinYu/LinYu.def`），不是 `packs/<id>/chars/...`。
  - 原因：引擎只认 `chars/`（`system.go:5531` 的默认子目录）与 def 相对目录（同目录自洽）。用「资产集原路径」当 vpath，引擎零改动即可命中。
- 挂载是**目录级前缀**：`chars/`、`data/`、`stages/`、`external/`、`font/`、`sound/`、`save/` 逐个前缀挂；未出现在资产集里的前缀不挂 → 兜底层同名文件仍在（stock 角色仍可选）。

### 2.3 覆盖层怎么挂（vfs.js 增补）

在 `vfs.js` 增加一张 **挂载表** `mounts: Map<vpath, {url, size}>`（vpath → 来源 URL + 字节数）：

| 能力 | 实现要点 |
|---|---|
| 注册 | `globalThis.ikemenVfsMount(prefix, baseUrl, files)`：`files` 为 `{vpath: size}`（资产集自带的 `manifest.json` 里就有，`workshops/.../manifest.json` 是现成的清单来源） |
| 存在性 | `exists()` / `sizeOf()` / `readdir()` / `stat()` 都要认挂载条目（否则 `FileExist` 找不到文件、`stat` 报 ENOENT） |
| 取内容 | `fetchFile(vpath)` 顺序：`contents`（L2 覆盖层）→ `mounts`（L1）→ `manifest`（L0 兜底） |
| 目录登记 | 挂载路径要过 `registerDirsFor()`，否则 `chars/` 目录读不出来 |
| Build ID | 挂载清单（路径 + 大小 + 来源 URL）参与哈希，否则两个玩家挂着不同资产集会算成同一个 Build ID，联机直接错版 |
| 懒加载 | 保持按需拉取：一个资产集 800 个文件，起打只拉用到的那 10 个角色的十几个文件 |

> 不走 `ikemenMods`（IndexedDB）做 L1 的原因：那是**浏览器本地存储**，PC 上有磁盘上的资产集却要往浏览器里再存一份，等于把「拷进引擎目录」换成了「拷进 IndexedDB」，一万个资产集一样撑爆。L1 应该是**按需从服务器直读**。

### 2.4 角色名单（`select.def`）改为运行时生成

- **不再**在 `ikemen-fs/file/data/select.def` 里硬编码角色列表（现在还指着已被删除的 `LinYu/LinYu.def`、`LinYuAI/LinYuAI.def`，是遗留脏数据）。
- 新增 `GET /api/packs/:dir/select.def`：服务端按资产集 `roster.json` / `mapping.json` / 实际 `chars/` 目录**生成** `[Characters]` 段（`id/id.def` 形式），`[ExtraStages]` 同理。
- 绑定后，前端把这个文件作为覆盖层注入 `data/select.def`（或让 L1 直接带 `data/select.def`）→ 引擎选人屏、随机角色池自动等于该资产集的角色集。
- 兜底 `data/select.def` 保留，但只列真正随站点分发的兜底角色。

### 2.5 前端「本地缺少 N 个角色」重新定义

旧语义（**错的**）：`资产集声明的角色 − 引擎目录里有的角色`。
新语义（按来源分别报）：

| 情况 | 提示 |
|---|---|
| 资产集自己目录里就缺这个角色（`chars/<id>` 不存在或没有 `.def`） | `⚠ 资产集缺少 N 个角色：…`（资产集自身不完整，需要补包） |
| 资产集有、但引擎兜底层没有（正常情况，不再是错误） | 不提示 |
| 兜底层有、资产集没有（可选的备用角色） | 不提示，或在选人屏标注「兜底角色」 |
| 该角色资源残缺（`BROKEN_CHARS` 那种跑不起来的包） | `⚠ N 个角色资源不完整，跑不起来：…` |

实现：`server/lib/packs.cjs` 的 `packCharPool(dir)` 已经是「`mapping.charPool` ∩ 该资产集 `chars/` 里有 `.def` 的角色」——**它本来就是对的**，只是前端没用它，而是去比了引擎目录。改前端即可：`missingPackChars()` → 改用服务端算好的 `packCharPool` 与 `charPool` 求差。

同时 `LOCAL_OK` 硬编码名单要拆成两个概念：

- `FALLBACK_CHARS`（随站点分发的兜底角色）——来自服务端 `localChars`（只读 `ikemen-fs/file/chars`，**只减不增**）；
- `PACK_CHARS`（当前绑定资产集的可跑角色）——来自服务端 `packCharPool(dir)`。

两者不再互相污染，也不再有「往 `LOCAL_OK` 里 push」这种写法（`index.html:1343`）。

### 2.6 其他跟着改的读路径

| 现状 | 改成 |
|---|---|
| `serve.cjs:35` `CHARS_DIR` 供 `/api/portrait` `/api/anim` 用 | 解析顺序：**当前资产集的 `chars/<id>` → 兜底 `ikemen-fs/file/chars/<id>`**；接口加 `?pack=<dir>` |
| `packs.cjs:214/252` `readCharMeta` / `writeCharMeta` 优先写引擎目录 | 改为**优先写资产集目录**（资产集拥有这些标记），引擎目录只读 |
| `patch-char-ai.mjs`（给角色打 `TriggerAll = Ailevel > 0`）打到引擎目录 | 改为打到**资产集目录**下的角色包 |
| `rebuild-manifest.mjs` | 只管兜底层；资产集不参与（资产集有自己的 `manifest.json`） |
| `android_h5/sync.mjs` 全量打包 `ikemen-fs` | APK 只带兜底层 + 演示用的那一个资产集（可选），不带全部资产集 |

## 3. 两种绑定形态

### 形态 A：仓库内资产集（PC 主路径）——**零拷贝**

- 资产集在 `workshops/toon-fighting-web/map_design/<dir>/`，或已登记到 `assets/assetpacks/<id>/`。
- 服务器直接能读这两个目录（`serve.cjs` 静态服务已覆盖整个仓库根）。
- 绑定时：服务端返回该资产集的 `manifest.json`（路径 + 大小）→ 前端 `ikemenVfsMount()` 挂上 → 引擎要哪个文件就 HTTP 拉哪个。
- **代价：0 拷贝、0 额外磁盘占用；一万个资产集只是登记簿里的一万条元数据。**

### 形态 B：用户自选文件夹（PC / 安卓通用）——浏览器侧覆盖层

- 用户用 `<input type="file" webkitdirectory>` 选一个**仓库外**的目录。
- 浏览器读到的只有元数据 JSON（现状如此）+ 资产二进制。资产二进制无法交给服务器（浏览器不暴露绝对路径），所以走 **L2 浏览器覆盖层**：`ikemenMods.add('chars/<id>/<def>', bytes)`。
- 前提：资产集总体积要在浏览器配额内（IndexedDB 常见配额数百 MB～数 GB，取决于浏览器/磁盘）。超大资产集建议走形态 A（放进仓库目录）或未来的「上传到 OSS + CDN」形态。
- 安卓端：APK 内只有兜底层；用户自选目录里的资产同样进 L2 覆盖层，**不写进 APK 资源树**。

> 形态 A 与 B 的差别只在「文件从哪来」，对上层（名单生成、角色池、`select.def`、对局逻辑）完全一致。

### 形态 C（后续）：OSS / CDN 资产包

资产集放对象存储，`baseUrl` 指 CDN，vfs 的挂载源换成 CDN URL。挂载表与覆盖层模型不用改 —— 这也是为什么 L1 要做成「URL + 大小」而不是「本地目录句柄」。

## 4. 改动清单（按文件）

### 4.1 `vfs.js`（新增挂载层）

- `mounts: Map<vpath, {url, size}>`；`exists/sizeOf/readdir/stat/fetchFile` 认它。
- `globalThis.ikemenVfsMount(prefix, baseUrl, files)` / `ikemenVfsUnmount(prefix)`。
- Build ID 计算里加入挂载清单。
- 保持「懒加载 + 失败即 ENOENT」语义，不预取全包。

### 4.2 `server/lib/packs.cjs`

- 新增 `packFiles(dir)`：读资产集自带 `manifest.json` → 返回 `{ vpath: size }` + 资源根 URL（相对仓库根的路径）。
- 新增 `packSelectDef(dir)`：按 `chars/` 实际内容 + `roster.json` 生成 `[Characters]` / `[ExtraStages]` 文本。
- `localCharIds()` 语义收紧为「兜底层可跑角色」，**只读**。
- `packCharPool(dir)` 保持「资产集自身角色 ∩ 自己目录」，作为前端唯一真源。
- `readCharMeta` / `writeCharMeta` 的优先级改为 **资产集目录 → 兜底目录**。
- `BROKEN_CHARS`（`98-kim`、`MasterRyu`）从「全局黑名单」降为「兜底层黑名单」。

### 4.3 `serve.cjs`

- `GET /api/packs/:dir/files` → `{ ok, baseUrl, files: {vpath:size} }`（供 vfs 挂载）。
- `GET /api/packs/:dir/select.def` → 生成的角色名单（`text/plain`）。
- `GET /api/portrait/:charId?pack=<dir>`、`GET /api/anim/:charId/:action?pack=<dir>` → 先查资产集目录，再查兜底目录。
- `GET /api/assetpacks` → 增加 `packChars: { [dir]: [charId] }`（各资产集自带的可跑角色）与 `fallbackChars`（兜底角色），前端不再自己合并名单。

### 4.4 `index.html`

- 删 `LOCAL_OK` 的 push 合并逻辑，改为 `FALLBACK_CHARS` / `PACK_CHARS` 两个只读集合。
- `missingPackChars()` 改为「资产集自身缺的角色」。
- `usePack(dir)` 之后调用 `ikemenVfsMount()` 挂 L1，并刷新 `select.def` 覆盖层。

## 7. 风险与红线

- **红线 1**：`ikemen-fs/file/` 只读。它是「引擎兜底资产 + 分发边界」，任何资产集都不得写入。
- **红线 2**：不因绑定资产集而重建/膨胀 `ikemen-fs/manifest.json`（那是站点分发清单）。
- **红线 3**：对局进行中不发起任何新的 HTTP 请求 —— 覆盖层必须**开打前**挂好；引擎按需拉文件发生在**加载阶段**（引擎加载角色资产在进战斗前，属加载期，不是对局中）。
- **红线 4**：版权。第三方角色包不进站点分发物；APK 只含兜底层。
- **风险 A**：挂载是「同 vpath 覆盖」，若资产集里的文件与兜底层同名但内容不同，会**静默替换**兜底文件（如 `data/common1.cns.zss`、`data/system.def`）。这是设计意图（资产集自带头文件），但必须让「资产集自带 data/ 与 external/」这件事在登记时显式声明（`pack.json` 增加 `overlay: { data: true, external: true }` 之类），避免用户误以为只覆盖了角色。
- **风险 B**：`external/`（Lua 脚本）被覆盖会改变引擎行为（不同引擎版本的角色包可能不兼容）→ 资产集应声明其引擎兼容版本。
- **风险 C**：形态 B 依赖浏览器 IndexedDB 配额 → 超限时降级提示「该资产集过大，请改用仓库内资产集 / CDN 形态」。
- **风险 D**：`stages/` 被覆盖时，`-s stages/kfm.def` 这类硬编码启动参数要跟着改成资产集里的实际舞台（现在 `index.html:3820` 写死 `kfm.def`）。

## 9. 附：术语

| 词 | 含义 |
|---|---|
| 兜底资产 | 随站点/APK 分发的通用角色与舞台（`ikemen-fs/file/`），是**默认集合**，不是资产集 |
| 资产集 | 一份自包含的角色/舞台/脚本集合（`pack.json` + 目录树 + `manifest.json`），自带二进制资产 |
| 覆盖层（L1/L2） | 运行时挂进 VFS、盖住兜底层的文件集合；L1 = 服务器直读，L2 = 浏览器本地 |
| 绑定 | 把某个资产集的覆盖层挂上 + 换名单，**不拷贝文件** |
| 角色池 | 当前上下文里可用的角色 id 集合 = 资产集自带角色 ∪（可选）兜底角色 |
